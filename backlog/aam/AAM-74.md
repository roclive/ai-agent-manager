## AAM/GW 本地 MLX 模型后端可选与实测路由

为 AAM 和 GW 的本地模型路由增加并验证 Ollama 与 omlx 两种后端的可选能力，覆盖三种模型：Gemma 4 E4B MLX 4-bit、LFM2.5-8B-A1B MLX 4-bit、LFM2.5-2.6B MLX 4-bit。目标是让实际可运行的模型可按模型选择/任务覆盖指定 `ollama` 或 `omlx`，并用测试证明选择、派发和失败回退一致；不同模型的后端支持须以真实 smoke 证据为准，不得因格式名称相同就假定任一后端可加载 MLX 权重。

1. 先阅读 AAM-39、AAM-72、AAM-73、AAM-60 与 GW-9/GW-10/AAM-62/AAM-63/AAM-64 的实现和证据，整理三模型 × 两后端的支持矩阵（加载、短生成、工具调用/编码 smoke）。未完成或失败项标 unknown/failed，不谎报支持。
2. 在 AAM 和 GW 的路由/配置中，支持对每个已验证模型选择 `ollama` 或 `omlx`，并支持明确的全局默认及单任务覆盖（依现有共享契约）。展示实际选择的模型、后端和路由理由；后端不可用或模型加载失败时，遵循现有回退规则并记录实际路径，不静默改道。
3. 为每种后端和路由路径编写 fake-based 自动测试：默认选择、按模型选后端、任务覆盖、能力过滤、模型/后端缺失、启动/请求失败回退、AAM/GW 共享运行锁与并发协调。CI 不调用真实 Ollama、omlx、编码 CLI 或云模型。
4. 有界真实性能比较采用相同机器、同一模型 revision、相同提示词/上下文/温度/并发与逐模型清理流程，顺序运行 Ollama 与 omlx 可用路径，记录加载耗时、TTFT、decode tok/s、峰值内存、成功率和工具调用有效率。引用 AAM-39 系列报告；只有缺少可比证据时才补跑必要 smoke，不同时加载多个模型。
5. 对 LFM2.5-2.6B，明确比较 omlx 相对 Ollama 的实际收益。如果 omlx 没有可重复且有实际意义的速度优势，且 Ollama 路径满足可靠性/功能要求，则推荐并配置由 Ollama 管理该模型；在报告中给出数据和选择理由。若收益显著或 Ollama 有兼容性问题，再保留 omlx 为推荐后端。不得只凭理论推断判断。
6. 更新 AAM/GW 路由说明及三模型后端支持矩阵，分别说明默认值、任务覆盖方式、各模型推荐后端和实测限制。模型真实 smoke 与 CI fake 测试结果分开报告。

约束：模型权重只放用户缓存；遵守 AAM-26 清理规则和 deny-list；单模型顺序测试、共享运行锁、硬超时及仅清理自有进程；不因该任务启用未验证模型的自动路由，不改动用户未授权的生产服务状态。
