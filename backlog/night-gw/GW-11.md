# M1 实测 mlx-dspark：LFM2.5-2.6B MLX 4-bit benchmark

前置：AAM-39

用户最新要求（2026-10-20，覆盖旧模型/前置/验收表述）：本任务先依赖 AAM-39，统一以 mlx-community/LFM2.5-2.6B-4bit 原生 MLX 模型开展测试、配置示例和集成；复用 AAM-39 的真实加载及短文本生成证据。原来要求以 Gemma4 为默认测试模型、等待 AAM-38/AAM-60 或要求多个真实模型都通过的表述不再作为本任务前置。保留本任务原有功能验收；多模型配置/路由的自动测试仍可使用两个以上 fake 模型，但真实集成只需此 LFM 模型，不为凑模型数量另下载或启用未验证模型。模型 smoke 只证明加载和生成可用，编码、工具调用等能力必须按本任务实际验证，不可由 smoke 推断。内存压力、swap、缺少峰值监测均不能作为跳过 smoke 的理由；内存仅作观测，保留共享锁、单模型运行、硬超时和仅清理自有进程的要求。

在 MacBook M1 16GB 实测 mlx-dspark + LFM2.5-2.6B 原生 MLX 4-bit。用户授权在独立 Python venv 安装必要依赖、复用/下载主模型和匹配 draft，并运行真实 benchmark；先只测 4-bit，不训练 draft，不测 BF16，不启用 --wired-limit。

1. 先核实官方项目、包来源、Python/MLX 要求和当前 CLI --help：确认 doctor、benchmark、--trials、--json、DSpark/Lookup 模式及 LFM2.5 draft 自动匹配是否真实支持。用户提供的命令和加速数据仅作待核实参考，不视为本机结果。
2. 精确核实主模型与 draft 仓库/revision、格式、许可、下载大小。优先复用 mlx-community/LFM2.5-2.6B-4bit 缓存，核实用户示例 LiquidAI/LFM2.5-2.6B-MLX-4bit 是否存在；主模型必须原生 MLX 4-bit，不以 GGUF 替代。检查已有下载，避免重复；主模型必要文件集上限 4GB，draft 上限 1GB，自动下载前核实匹配目标和大小。记录安装版本、来源及缓存路径，模型/venv/缓存不得入 git。
3. 有界执行 doctor（若支持）、真实加载和短生成，再执行 3 trials benchmark。按官方实际 CLI 比较普通 decode、DSpark 和可用 Lookup；固定 prompt、输出长度与采样设置，记录每次 tok/s、TTFT、生成 token 数、预热与缓存、加速比、draft acceptance、每轮接受 token 与最佳 draft cap（未提供指标记 unknown）。保存原始 stdout/stderr 和 JSON；不得把上游 M4 Pro 数据或示例数值算作 M1 实测。
4. 使用共享模型锁，单模型顺序运行；有其他任务占锁则排队并记录持有者，不绕锁。不因内存压力、swap 或缺少峰值监测跳过真实 smoke，内存仅作观测。保留硬超时与自有进程清理；不关闭用户应用、不 sudo purge、不停止 AAM/UI、OntoKB、Paperclip、Claude/Codex/ChatGPT 或其他任务进程，结束后卸载本次模型。独立 venv 不改变现有 omlx/Ollama/GW 环境。
5. 交付 reports/mlx-dspark-lfm26b.md 及原始 JSON/日志，说明兼容性、加载和短生成结果、速度与加速收益是否可重复，以及是否值得后续接入 GW。失败保留真实错误，不虚构支持；不自动变更生产路由/默认模型。项目现有 test_cmd 必须通过，新增代码用 fake runner/fixture 验证，CI 不下载/加载模型或调用真实编码 CLI。禁止 git push。
